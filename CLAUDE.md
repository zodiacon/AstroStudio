# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

AstroStudio is a native Windows desktop astrology application built with C++20, WTL (Windows Template Library), and Direct2D/DirectWrite. It calculates and draws natal/chart data (planets, houses, aspects) using the Swiss Ephemeris library.

## Build

This is a Visual Studio solution (`AstroStudio.sln`), not a CMake/cross-platform project. Build with MSBuild or Visual Studio 2022+ (toolset v145, targets Win32/x64/ARM64, `stdcpp20`).

```
msbuild AstroStudio.sln /p:Configuration=Debug /p:Platform=x64
```

There are no lint configs or CI workflows in this repo. `AstroCore` has unit tests (below); everything else is verified by building and running the app (`x64\Debug\AstroStudio.exe`).

### Tests

`AstroCore.Tests` is a Catch2 v3 console project (x64 only, Debug and Release) covering `AstroCore`: `DateTime`, `AstroPoint`, `Aspects`, `AstroCalculator` (positions, houses, ingresses, stations - checked against equinox times, J2000 and the 2024 Mercury retrograde, using the built-in Moshier ephemeris so no data files are needed) and `ChartData`. Build the solution, then run `x64\Debug\AstroCore.Tests.exe` (`[DateTime]` etc. select by tag; the exit code is 0 when everything passes).

- Catch2 comes from vcpkg in classic mode (`E:\vcpkg`, integrated with MSBuild). The project uses the `x64-windows-static` triplet (`VcpkgUseStatic`) because AstroCore and sweph use the static CRT (`/MT`); `VcpkgAutoLink` is off and Catch2 is linked explicitly (`Catch2Main` lives in `lib\manual-link`). The solution's x86 configuration doesn't build it (no x86 Catch2 installed).
- To record a bug you haven't fixed yet, write the test for the correct behaviour and tag it `[!shouldfail]` (Catch2 counts a failure as a pass and starts complaining when the bug is fixed - then remove the tag). There are none at the moment.
- `DateTime::Get` works in whole milliseconds on purpose: splitting the day fraction with doubles made a whole minute read back as the previous minute plus 59.99999 seconds. `AstroPoint::MidPoint` is the midpoint on the shorter arc, and `IsBetween(start, end)` is the range running forward from `start` to `end`, through 0 Aries if `end` is the smaller number.

### Submodules

`WTLHelper` is a git submodule (https://github.com/zodiacon/WTLHelper). Run `git submodule update --init` after cloning if it's empty.

## Solution structure

The `.sln` builds five projects: `AstroStudio` (the app), `AstroCore` (calculation engine), `sweph` (Swiss Ephemeris, vendored C library), `WTLHelper` (submodule, shared WTL UI helper library used across the author's other projects) and `AstroCore.Tests` (Catch2 tests for `AstroCore`, below). There were once `CairoGfx` and `QChart` alternative rendering backends in the repo; they were unused and are gone (the app draws with Direct2D).

- **`sweph/`** — Vendored Swiss Ephemeris C sources (`swe*.c/h`). Treat as third-party; avoid modifying unless fixing a vendoring issue.
- **`AstroCore/`** — Platform-agnostic astrology calculation engine, no UI/WTL dependencies.
  - `DateTime` — Julian day based date/time type (Gregorian/Julian calendar aware).
  - `AstroPoint` — zodiac position type; `Planet`, `ZodiacSign` enums.
  - `AstroCalculator` — thin wrapper over `sweph` for planet positions, house cusps, ingresses, stations, eclipses (`CalcEclipses`, from `swe_sol_eclipse_when_glob`/`swe_lun_eclipse_when`) and the Moon's void of course periods (`CalcVoidOfCourse`: from the last exact conjunction/sextile/square/trine/opposition to the Sun and planets - through Pluto unless `outerPlanets` is off - until the Moon leaves its sign; found by stepping two hours at a time and bisecting the last crossing, and if there is none the void is the whole stay in the sign, `WholeSign`).
  - `ChartData` — the aggregate for one chart: planets, houses, harmonic, `ChartInfo` (person/event birth data). `CalcHouses`/`CalcPlanets` populate it via an `AstroCalculator`.
  - `Aspects.h` — `AspectCalculator` computes aspects (conjunction, trine, square, ...) between planet positions from `AspectSettings` (orbs).
- **`AstroStudio/`** — The WTL application.
  - `MainFrm` (`IMainFrame`) — main frame window; owns a `CNativeCustomTabView` hosting one tab per open chart. Creates new chart views via `AddChartView`.
  - `ChartView` (`CChartView`) — one chart's tab content; splits between `ChartDetailsView` (text/list data) and `GraphicChartView`.
  - `GraphicChartView` (`CGraphicChartView`) — renders the circular chart wheel via `D2DChartDrawing` onto its own `ID2D1HwndRenderTarget`.
  - `D2DChartDrawing` — Direct2D/DirectWrite drawing logic for the chart wheel (zodiac belt, houses, aspect lines) in a 1000x1000 logical space, parameterized by `ChartDrawingParameters` (colors, widths, toggles). `Draw` does not call `BeginDraw`/`EndDraw`; the owning view does.
  - **Interactive wheel** (`CGraphicChartView` + `D2DChartDrawing`): hovering a planet or an aspect line shows a tracking tooltip (`PlanetTip`/`AspectTip`: position, house, speed, the planet's aspects; orb and applying/separating for a line); clicking a planet highlights it and fades every aspect that isn't its own (click it again, or an empty spot, to let go); dragging turns the wheel (`Rotation`, degrees counterclockwise, default 0 = ascendant at the left; two quick clicks on an empty spot turn it back). Picking and rotation belong to the view, not the chart, and show in copies and exports. `D2DChartDrawing` records where it put planets and aspect lines during `Draw` (`m_planetSpots`/`m_aspectLines`), and `HitTest` works from those in the 1000x1000 space, so it only knows what the last `Draw` drew. Every angle in the drawing goes through `PointByAngle`, which applies the rotation; the zodiac belts use screen angles and subtract it separately. Clicking the wheel takes the keyboard focus so Ctrl+C copies the picture. `CGraphicChartView::Refresh` keeps a planet's tooltip (with new values) but drops an aspect's, since aspect indexes change. The tooltip window is only touched when its text or position changes (`ShowTip`): re-setting the same text, or moving to the same place, makes it repaint, which flashed on every mouse move and Live tick. It is created lazily, so the dark style is applied each time it is shown (`DarkMode::setDarkTooltips`) - the program can change modes while it exists.
  - **Transits** (`Chart > Show Transits`, the `Transits` toolbar button, `ID_CHART_TRANSITS`; `CChartView::SetTransits`/`UpdateTransits`): the wheel becomes a bi-wheel - the chart shrunk to `BiWheelScale` (0.87, a transform about the center in `D2DChartDrawing::DrawChart`, so natal glyphs shrink too) inside a band holding the transiting planets (glyphs at r=468, dots at r=441, in a band 62 wide, in `TransitColor`) and a caption with their time in the chart's zone. `m_TransitData` is a second `ChartData` with the chart's planets, place and zone, starting at the current time; it is planets only (no houses) and the natal harmonic applies. Its aspects to the natal planets (`AspectData` with Planet1 = transiting, Planet2 = natal; major aspects only, 3 degrees - set in `UpdateTransits`) are drawn as lines from a transit dot to the natal dot, and the natal chart's own aspects are not drawn while transits show. **Step, Auto and Live move the transits' time while they are shown (`StepTime`/`TickLive` pick the target); the chart keeps its own time**, so none of it marks the chart modified. Hit testing knows four things (`ChartHit::Kind`: Planet, Aspect, TransitPlanet, TransitAspect) and a highlight is a `ChartSelection` (planet + whether it is the transiting one), so a natal and a transiting Sun can be told apart. The aspect grid and list, and chart files, know nothing about transits (yet).
  - `AspectGridWnd` / `AspectGridDrawing` — the aspect grid tab, drawn the same way (its own render target; `AspectGridDrawing::Draw` also leaves `BeginDraw`/`EndDraw` to the caller).
  - `D2DResources` — process-wide singleton (`D2DResources::Get().Ensure()`) holding everything device-independent: the D2D and DirectWrite factories, the embedded glyph-font collection and the text formats. Only render targets are per window (`CreateWindowRenderTarget`, fixed at 96 DPI so a DIP is a pixel). The project targets Windows 8.1 in `pch.h`, which hides the DirectWrite in-memory font loader; `D2DResources.h` raises `NTDDI_VERSION` around its d2d1/dwrite_3 includes only. There is no GDI+ anywhere in the app — don't reintroduce it.
  - `ChartImage` — the chart wheel as a picture: `Render` draws `D2DChartDrawing` into a WIC bitmap (`CreateWicBitmapRenderTarget`, 96 DPI, `DefaultSize` 1600 px), `SavePng` encodes it, `CopyToClipboard` puts it there as a `CF_DIB`. `CGraphicChartView::RenderImage` feeds it. **Copy / Export**: in a chart, Edit > Copy (Ctrl+C) copies the wheel as a picture unless a text box has the focus, when it is the text box's own copy (`CChartView::OnEditCopy`); `File > Export...` (`ID_FILE_EXPORT`, routed to the active page like Save) writes a PNG. In the ephemeris, Copy puts the selected rows on the clipboard as tab-separated text and Export writes every row as UTF-8 CSV with a BOM (for Excel); both use plain text (no glyphs) and the columns in the order shown (`BuildTable`). Export is enabled by the page that can do it in its `PageActivated` (the frame disables it at start and pages call `UIEnable(ID_FILE_EXPORT, ...)`), so a new view type that exports must do the same.
  - **Ephemeris options** (`Options` toolbar button, `ID_EPHEMERIS_OPTIONS`, `CEphemerisOptionsDlg` / `EphemerisSettings`): the start date (day and month drop-downs and a year box, like the New Chart dialog; the day list follows the month and year, and the days the 1582 reform skipped are refused), the step in whole days (1-366; a row's date is `m_StartTime + m_Increment * row`), the bodies (any of the 20 in the list, not just the standard set) and two extras (eclipses, and a column for the Moon's void of course). `CEphemerisView::ApplySettings` starts the list over (`RebuildColumns`, which `Clear`s and re-adds the column manager's columns; `ColumnType::Planet` and above are the bodies, one per `m_Planets` entry). **Eclipses** go into the Phenomena column (`GetRowPhenom`): `Solar total eclipse (18.17)` in words, and with glyphs on - the glyph font has no letters - Sun, conjunction (solar) or opposition (lunar), Moon and the time, `☉ ☌ ☽ (18.17)`, so the kind of eclipse shows only in words. Because a glyph triple is easy to miss, the Phenomena cell of a row with an eclipse is tinted (`RowData::HasEclipse`, set in `GetRowPhenom`; `OnSubItemPrePaint` calls it first, since the cell can be drawn before its text is asked for). The **Moon void of course** column is a column of its own. The two are offered only for steps up to 31 and 7 days. The void column follows the Glyphs button like Phenomena: with glyphs on it is in the glyph font and holds only glyphs, numbers and dashes (`06.33 - 07.41 (☍ ♂)`; a dash is the open end of a void that began before the row or goes on after it, `(-)` means no aspect in the sign) - the font has no letters - and with glyphs off it is in the plain font with words (`from 23.08 (opposition Mercury)`). `RowData` keeps both (`VoidGlyph`, `VoidText`); the clipboard and CSV get the words. A row whose cell has a void in it is tinted purple, like eclipse rows are amber (`OnSubItemPrePaint` computes the row's extras first); the purple is stronger the more of the row's stretch of time the Moon is void (`RowData::VoidFraction`, from a hint at 0 up to full strength at 1). A row's cell lists what falls between its date and the next row's (`GetRowPhenom` for eclipses, `CalcExtras` for voids); eclipses and voids are worked out a stretch at a time as rows are asked for and kept (`EnsureEclipses`/`EnsureVoids`; exporting all 2000 rows with the void column takes some seconds in a Debug build).
  - `EphemerisView` — ephemeris/table-style view. Its toolbar has a second rebar band (`CPlanetStrip`, band `NowBand`) with every listed body's current longitude (UT now), refreshed by a 30-second `WM_TIMER`; it follows the Glyphs/Seconds/font-size toggles, and `UpdateNowStrip` resizes the band to the font.
  - `NewChartDlg` (`CNewChartDlg`) — the `File > New > Chart...` dialog (name, type, location, date, time, time zone, house system). `IMainFrame::NewChartWithDialog(initial)` shows it and opens the chart; `CEphemerisView` calls the same thing prefilled with noon UT of the selected row's date (for now), which the dialog shows as local time in the machine's zone like any other time.
  - `TimeZones` — Windows time zone list (`EnumDynamicTimeZoneInformation`) plus local↔UT conversion. **`ChartInfo::Time` is always UT**; `ChartInfo::TimeZone` says how to show it: `Name` is a Windows zone key (its DST rules for that year are used), or empty for a manual fixed `OffsetUT` (minutes east of UT). Windows only knows years 1601+ and thin pre-1970s DST history, hence the manual override; outside its range the zone's standard offset is used.
  - **Place lookup** (the Lookup button, `CLocationControls::BeginLookup`/`EndLookup`): `NetworkHelper::SearchPlaces` queries Open-Meteo's geocoding API (GeoNames data, CC BY 4.0 - credited in the About box; free tier is non-commercial only) on a worker thread and posts `WM_LOOKUP_RESULT`; several matches are picked from a popup menu. The result's IANA zone is mapped to a Windows zone with ICU (`TimeZones::WindowsKeyFromIana`, `ucal_getWindowsTimeZoneID`) - the *legacy* `icuuc.lib`/`icuin.lib`, so the app still runs on Windows 10 1709 (`icu.lib` would need 1903); they need COM initialized on the calling thread, so map on the UI thread. The mapping is many-to-one (lossy for old dates); in `NewChartDlg` it selects the zone, in `ChartDetailsView` only the location changes (a zone change would change the chart's UT).
  - **Chart files** (`.chart`; File > Open Chart / Save / Save Chart As): `ChartFile::Save/Load` write a `ChartData` as a UTF-8 INI text file meant for hand editing (`[Chart]` version/house system/harmonic/planets by name, `[Person]`, `[Time]`, `[Location]`; the format is documented at the top of `ChartFile.h`). The time is stored as *local* date/time plus `TimeZone` (Windows zone name) and `UtOffset`; UT is derived on load, and `UtOffset` breaks the tie for the repeated hour when DST ends and is the fallback for a zone this machine doesn't have. Positions are never stored. Loading is strict and reports `[Section] Key (line N): what's wrong`. The INI reader/writer is `IniDocument` in **WTLHelper** (not the older `IniFile` there, which wraps GetPrivateProfile*); it saves via a temp file so a failed save can't damage the existing one and rewrites the whole file (comments in a hand-edited file are not kept).
    - `CChartView` owns the file path, a modified flag and the tab title: the tab shows `name *` only for a chart that has a file (opened or saved) and has changed since; a chart that was never saved shows no marker but still asks. Any `WM_RECALC` (details view edits, Now/Here/Lookup, manual stepping) counts as an edit, except while `m_NotModifying` is raised (the startup location filling in, Auto Step ticks).
    - **Recent files**: WTL's `CRecentDocumentList` (`CMainFrame::m_Recent`) fills in at the `(empty)` placeholder (`ID_FILE_MRU_FIRST`) inside the File menu's `Recent Files` submenu (`OnCreate` finds that submenu by the placeholder's ID, so it can move); `AddRecentFile` is called by the frame after an open and by `CChartView::Save` (via `IMainFrame`). It holds 8 entries and is kept in `HKCU\Software\AstroStudio` (`RecentFilesKey` in `MainFrm.cpp`), written on every change. Picking a file that no longer exists says so and drops it. The placeholder is disabled through the UI map (`UIEnable`) when the list is empty, otherwise the menu updater would re-enable it.
    - Closing asks first: `IView::CanClose()` (default true) is called by the frame for Window > Close, Close All and exiting (`CMainFrame::OnClose`); a chart with unsaved changes asks "Save changes?" (Yes saves, No discards, Cancel stops the closing). New views with state to protect override it.
    - The frame finds a tab's view with `dynamic_cast<IView*>` on the page data (`ViewOfPage`); don't cast page data to a concrete view type - pages are of different kinds.
  - **Time stepping** (the chart view's toolbar: Back / Forward buttons, a 1-30 count and a unit drop-down; also `Chart` menu and Alt+Left / Alt+Right): `CChartView::StepTime` calls `TimeStep::Step`, then sends `WM_RECALC` and `CChartDetailsView::UpdateControls` like `Now` does. Seconds/minutes/hours are exact UT durations; days/weeks/months/years are calendar steps in the chart's own wall-clock time (21:00 stays 21:00 across DST); a month/year step clamps to the month's last day and skips the days of the 1582 reform; results outside -3000..3000 are refused. The label and combos are child windows placed on toolbar separators (created *before* the toolbar joins the rebar, which sizes the band from its buttons). Commands reach the active chart page through `ALT_MSG_MAP(1)`; the menu items are enabled only while a chart page is active (`PageActivated`). `WINDOW_MENU_POSITION` in `MainFrm.cpp` is the index of the Window menu - keep it in step when adding menus. **Live** (the `Live` check button, `Chart > Live`, `ID_CHART_LIVE`) keeps the chart at the current time: on the same timer and interval as auto step (`SetLive`/`TickLive`, which set `Info().Time` to `DateTime::Now()` and refresh the zone's offset), excluding it, and disabling Back/Forward too (`UpdateStepUI` owns those states). Ticks don't mark the chart modified (`m_NotModifying`); any other `WM_RECALC` - the user changing the time or place in the details view - ends Live. **Auto step** (the `Auto` check button, `Chart > Auto Step`, and the interval drop-down of 100 msec to 10 sec) steps forward by the current count and unit on a `WM_TIMER`; it switches itself off at the year limit, and is per chart. While it is on, Step Back/Forward are disabled (buttons and menu) and `OnStep` ignores the Alt+Left/Right accelerators, which a disabled menu item doesn't block. Its timer runs only while that chart is the active page - `PageActivated` starts/stops it and re-applies the check state, since the frame's menu and every toolbar share one UI map. That relies on the frame announcing page changes: `SetActivePage` alone does not send `TBVN_PAGEACTIVATED` (only a real tab click does), so `CMainFrame::OnWindowActivate` sends it by hand - do the same for any other code that switches pages.
  - `TimeControls` / `LocationControls` — the date (day/month combos + year edit, so pre-1752 and Julian-calendar dates work), time (one text box, shown as 24-hour `HH:MM:SS`; `CTimeControls::ParseTime` accepts `2145`, `21:45`, `9.30`, `9:30 pm`, `12 am` ...), time zone and lat/lon controls, shared by `ChartDetailsView` and `NewChartDlg` through common control IDs (`IDC_DAY`, `IDC_LATDEG`, ...). Owners keep the message handling and call into these. Dates before 15 Oct 1582 are Julian; the year range is the built-in ephemeris' (-3000..3000, 0 = 1 BC).
  - **Settings** (`AppSettings.h`): `AppSettings` derives from WTLHelper's `Settings` and declares its values with the `BEGIN_SETTINGS`/`SETTING`/`DEF_SETTING` macros (the same way as TotalRegistry's `AppSettings`). One global instance (`g_Settings` in `AstroStudio.cpp`, reached with `AppSettings::Get()`); `WinMain` loads it (`Settings::Load`: `AstroStudio.ini` next to the program if there is one, otherwise `HKCU\Software\AstroStudio\Settings`) *before* dark mode is set up, and `CMainFrame::OnDestroy` saves it. Parts of the program read their values when they are created and write them as the user changes them (in memory; nothing is written until the window closes, so a crash loses the session's changes). Kept: window placement (`MainFrm`/`Run`, ignored if the place is off every monitor), dark mode (-1 until the user chooses: the system's), the status bar, the last house system, the chart view's step count/unit/interval, and the ephemeris toolbar states, step, bodies and extras. **Not** kept: the ephemeris start date (a month before today), transits, Live/Auto. The recent files list is separate (`HKCU\Software\AstroStudio\Recent Document List`, WTL's). Setting names must not be the name of a type used inside `AppSettings` (`StepUnit` clashed with the enum, hence `ChartStepUnit`), and `DEF_SETTING` reads bools as `int`. To add one: `SETTING(...)` + `DEF_SETTING(...)` in `AppSettings.h`, read it where the thing is created, write it where the user changes it.
  - `Interfaces.h` — cross-view contracts: `IMainFrame` (what views can call on the frame) and `IView` (what the frame can call on a tab page: `PageActivated`, `ProcessCommand`). New views should implement `IView`; new frame-level operations should be added to `IMainFrame`.
  - `ViewBase.h` (`CViewBase<T, TBase>`) — CRTP base every tab view derives from; wires up `IView::PageActivated`, idle-driven toolbar UI updates (`CAutoUpdateUI`), and self-deletion on `WM_DESTROY`/`OnFinalMessage`. New tab views should derive from this rather than reimplementing the plumbing.
  - `NetworkHelper` / `WinHttp` — WinHTTP-based lookups (e.g. external IP, geocoding-ish info) used to fill in `ChartInfo` (location/timezone) for "chart for now" style birth data.
  - `AstroFont` / `DefaultFont` — embeds/loads `res\HamburgSymbols.ttf` (the zodiac/planet glyph font) so it renders without being installed system-wide — see commit history for why (avoids requiring a global font install).
    - **`Helpers::LoadAstroFont` loading the font twice is not redundant.** `AddFontMemResourceEx` registers the face with GDI, which is what `CFont`/`CreatePointFont` lookups by name need; DirectWrite cannot see that registration, so `D2DResources` builds its own font collection from the same embedded resource (in-memory font loader + font set builder). Don't "simplify" either away.
    - The glyph tables in `DefaultFont.cpp` must cover their whole enum. `Planet` runs to Vesta (21) while HamburgSymbols originally stopped at Chiron (16), so the last five read past the end. A `static_assert` now ties the planet table's length to `Planet::NumPlanets`, so adding a body fails to compile until it has a glyph. Codes come from the "INDEX #" column of `HamburgSymbols.pdf`.
  - `PlanetSpacer` — layout helper to avoid overlapping planet glyphs when several planets cluster together on the wheel.

## Conventions

- Views communicate with the main frame only through `IMainFrame`/`IView`, not concrete types — keep new cross-view interactions going through those interfaces.
- `AstroCore` must stay free of WTL/Direct2D/UI includes; calculation logic belongs there, drawing/UI logic belongs in `AstroStudio`.
- Dark mode is handled via `WTLHelper`'s `WTLHelper::InitDarkMode()` / `ThemeHelper`; the app toggles it at runtime (`ID_OPTIONS_DARKMODE`) — UI code should get colors from the theme helpers rather than hardcoding them where dark-mode correctness matters.
  - WTLHelper detours `GetSysColor`/`GetSysColorBrush` in dark mode. Never hand out the DarkMode library's own brushes from that detour: callers assume a system brush isn't theirs to delete, and the shell's AutoComplete (it starts as soon as the user types in a file dialog's File name box) deletes the `COLOR_3DFACE` one. The library then paints with a dead handle and every control created afterwards, edit boxes and combos included, comes out light. The detour has its own brushes, validated on each call (`SafeBrush`).

## Gotchas

- Keyboard messages reach a page's dialog only if it handles `WM_FORWARDMSG` and passes it to `IsDialogMessage` (see `CChartView::OnForwardMsg` and `CChartDetailsView::OnForwardMsg`); the details view's Apply is its default button, so Enter applies.
